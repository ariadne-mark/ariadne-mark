CJ-05 — методика измерения 0.7.3a4

Измеряем фактический SDK.mark(): watermark, кодирование/ремукс, C2PA,
реестр, fsync и финальный read-back. Проверку измеряем отдельным SDK,
который не прогревался экспортом и не получает ожидаемый ID как подсказку.
Ожидаемый ID нужен только для последующей оценки ответа.

Основной корпус: два изображения и семь видео. Шесть H.264 роликов покрывают
720p/1080p, 5/10/15 секунд и 24/30/29.97 fps. Седьмой — HEVC 720p/10с.
Все входы созданы собственными детерминированными Pillow/FFmpeg процедурами.
Это инженерные данные, не выборка реальных приложений или durability/FPR корпус.
Источник, команда, хэш, время подготовки и полный ffprobe сохраняются.

Для каждой ячейки: один новый процесс и три последующих задания в resident SDK.
Холодный запуск означает процесс/SDK/модель, а не download/install/build или
холодный кэш ОС. Кэш ОС не очищается. Контейнерный старт показан отдельно.
Для положительных проверок используются четыре отдельных экспорта/ID,
а для чистых отрицательных — тот же исходник без маркировки.

У всех прогонов одинаковый image ID, 2 vCPU, 4 GiB cap и два потока.
Общая flock блокирует параллельные квалификационные задачи. Существующие
четыре сервиса не останавливаются; загрузка/steal и доступная RAM хоста
фиксируются. Каждый тяжёлый тест выполняется последовательно.

Канонический CPU: разность host cgroup v2 cpu.stat до/после операции.
Он включает Python, Node, FFmpeg/ffprobe и уже завершившихся детей.
Нативная работа FFmpeg через PyAV может идти в процессе Python: CPU роли
Python не означает интерпретируемый Python-код. Диагностическая декомпозиция:
SELF + reaped children + прирост CPU живых детей. При shutdown reaped включает
весь lifetime Node, поэтому shutdown исключается из сравнений операций.

Канонический пик памяти: memory.peak cgroup, сброшенный и прочитанный через
один FD на host Linux. Включает resident state, native/child memory и charged
page cache. Сброс проверен отдельной калибровкой. Это не RSS и не 4 GiB cap.
Также сохраняются memory.current/anon/file и sampled aggregate RSS каждые
100 мс. Shared mappings могут повторно учитываться при сумме RSS;
отдельные максимумы ролей нельзя складывать как общий физический пик.

Основной scope — current для нового issuer, как в инструкции первого внедрения.
Это не полная проверка всех исторических схем. Отдельный all-контроль на том же
720p/10с файле показывает цену более широкого scope с доступным legacy движком.

Metadata-loss: MP4 remux с -c copy и проверкой одинакового compressed essence
hash; изображения сохраняются в PNG с идентичным decoded RGB hash. Для JPEG
это переход JPEG→PNG без дополнительной lossy-кодировки, а не утверждение
об идентичности контейнерных bytes. Отсутствие C2PA проверяется перед замером.
Ищем ID/реестр, не объявляем изменённый файл криптографически аутентичным.

Контроли: 60с чистый ролик — cold+warm, результат budget/incomplete сохраняется
отдельно. Ещё один проход 720p/10с выполняется без periodic sampler для проверки
влияния измерителя на wall time; kernel peak и CPU deltas остаются включёнными.

В отчёте: n, median/min/max warm; cold точка с n=1. Никаких p95 из трёх повторов,
SLA, популяционных оценок accuracy/FPR или юридического минимального cadence.
Dev-подпись; production CA/TSA, сеть и HTTP/JWS overhead не включены в основной
SDK API timing. Это отдельные deployment затраты, не нулевые по умолчанию.

Raw row и timeline записываются после каждой операции, failures не удаляются.
SDK, модели, режимы, cadence/strength и default Economy5s не изменяются.
