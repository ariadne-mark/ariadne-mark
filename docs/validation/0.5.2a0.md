# 0.5.2a0 — release-readiness candidate

Reviewed on 4 November 2026. This is a candidate record, not a statement that
all publication gates have passed. The final commit/artifact hashes and CI
results belong in the release manifest after qualification.

## Changes

- C2PA Python 0.38.3 / native 0.91.7 via an explicit checksum-verified upstream
  bootstrap. The upstream Python tag exists but this version has no PyPI files.
- pip 26.3 and npm `adm-zip` 0.6.1; old provisioning caches are rejected.
- Multi-stage runtime, tested Node 24.22.2, npm restricted to the build stage.
- Temporary decoder cleanup, restartable worker cleanup handlers, production
  trust-file validation and H.264/HEVC/AAC input decoder allowlist.
- Official California consolidated/chaptered source reconciliation, recorded
  separately from actual legal/technical coverage.

## Functional evidence

An installed candidate with the dependency/API changes passed **89/89 tests**
on the Oregon m6a.large host, 2 CPU / 6 GiB container limit, no network,
read-only filesystem and bounded temporary storage. Run time: 198.708 seconds.
This includes real image/video engines, signing, legacy reading, verifier,
worker restarts and the additional resource/provisioning regressions.
The subsequent legal catalog update passed all 16 planner scenarios.

These are not benchmark results or a whole-product compliance assessment.
The final packaging revision and clean installation are qualified separately.
Historical 0.5/0.5.1 performance and 45 HTTP product-acceptance checks are
retained as historical evidence, not relabelled as tests of this revision.

## Dependency security evidence and limits

The updated Python candidate has no known pip-audit findings in resolved
packages; source-built C2PA and CPU-tagged Torch packages are skipped by that
scanner. A normalized-version OSV query for C2PA 0.38.3, Torch 2.14.1 and
Torchvision 0.29.1 returned no entries. That does not audit embedded native/Rust
transitive libraries. npm audit returned zero findings after the zip override.

Full filesystem scanning still reports Debian/FFmpeg native advisories. Removing
the Debian Node/npm toolchain reduced the OS inventory from 665 to 292 packages
and removed the reported postcss/undici entries. Remaining libxml2/FFmpeg and
other OS findings are not silently suppressed or described as fixed. Decoder
allowlists narrow the media surface but do not prove malformed media safe.
A reported setuptools 70.3.0 entry came from embedded SBOM data; installed
setuptools is 84.2.1. The final image also removes base site-packages before
copying the build environment, avoiding stale pip metadata.

The raw audit reports, scan logs, bootstrap source hashes and runtime inventory
are retained in project research evidence. Publishing a combined Docker binary
requires its own native triage and applicable GPL corresponding-source/notices
work. The first alpha's own wheel/source do not bundle those binary dependencies.
