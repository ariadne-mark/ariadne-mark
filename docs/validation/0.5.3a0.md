## Motion evidence and cost

The external synthetic-pan experiment was repeated on the Linux x86-64
m6a.large host with the installed native 0.91.7/C2PA 0.38.3 bundle, 2 CPU /
6 GiB container cap. On the 720p24, 5-second panel, Fast v2 recovered 5/5
sampled IDs at 0/0.5/2/10 px per frame; model calls were 5/86/120/120 out of
120 frames. Resilient used 120 model calls and recovered 5/5 in the panel.
This is a small synthetic regression panel, not a durability SLA or a
whole-video guarantee. On substantial movement Fast approaches Resilient's
cost. Historical v1 speed evidence must not be relabelled as v2 performance.

The external experiment's final pgrep-based process-count section did not run
in the minimal Linux image (pgrep absent); its eight motion results completed.
Worker restart/closure is assessed by explicit SDK regressions instead.

## Additional changes and remaining work

Native ONNX runtime files, including versioned shared libraries, are recorded
in installation receipts and checked before loading. npm lifecycle scripts
are disabled for the prebuilt CPU runtime. The wheel includes third-party
notices, and the sdist includes the stock-product Dockerfile. Public metadata
strings are classified as development, untrusted-signer or trusted-signer claims.

The Article 111(4) transition is classified as statutory law, not Commission
guidance. The voluntary Code's 3.4(c) signatory interoperability deadline is
flagged separately. Full Code/Guidelines adherence and a product legal opinion
remain unperformed.

The broader P2 backlog remains explicit: orphan staging/receipt reconciliation,
hard isolation/deadlines for every native inference engine, fork lifecycle
constraints, optional CORS/cross-provider detection and full native advisory
triage. These are not silently called fixed by this patch. Current staging
is adjacent to output; public file serving must use explicit download routes.
