# Validation — 0.2.0a0

Tested on 2026-11-03, AWS m6a.large (x86-64, 2 vCPU, 8 GiB host), Ubuntu 24.04,
with the repository Dockerfile. Containers were limited to 2 CPUs / 6 GiB and
ran media processing with `--network none`. No GPU or hosted signing/watermark
API was used. The real-engine suite also ran with a read-only root filesystem.

## Evidence

- **31 tests passed** in the real-engine container. [Test log](results/media-tests-0.2.0a0.log): signed PNG/JPEG/alpha,
  metadata-loss recovery, parent lineage, signature tampering, failed export,
  VFR/rotation/vertical MP4, AAC packet preservation and HTTP cleanup.
- [Raw CPU/durability report](results/cpu-smoke-0.2.0a0.json).
- [Installed package inventory](results/linux-python312-packages.txt).
- The PR/CI check `CPU media integration` repeats the actual engines; core-only
  unit tests are not substituted for this job.

## Measured smoke results

Four synthetic images at 1024×768: median complete export **0.505 s** after
loading the model. Image PSNR ranged **44.05–50.73 dB**. Cold initialization was
**2.924 s**. Peak Python process RSS was **808768 KiB** (about 790 MiB); this
excludes separate FFmpeg processes and is not a total-container memory limit.

Two 2-second / 24-frame videos took **7.734 s** at 512×320 and **9.497 s** at
720×1280. Both retained the correct ID after H.264 CRF 28 recompression. These
small samples are not a production throughput or latency SLA.

**23/24 image transformation checks recovered the correct ID.** The remaining
failure was the flat-color fixture after JPEG quality 50. An earlier run also
failed to recover a cropped greeting-card fixture, so cropping is not guaranteed.

A repeated video qualification used eight random IDs on the same vertical
fixture: **8/8 exports passed**, with a 1.5× video watermark residual and CRF 18.
Mean decoded-frame PSNR was 33.72–33.78 dB relative to the already-compressed
source (includes codec/color conversion losses). See [raw video report](results/video-payloads-0.2.0a0.json)
and [reproduction script](../../benchmarks/durability/video_payloads.py). This is
a narrow repeated-payload check, not a guarantee across arbitrary videos.

No wrong IDs were returned in this matrix; none of four unmarked controls
returned an Ariadne ID. Four controls cannot establish a production false
positive rate. No statistical robustness or legal durability threshold is
claimed. Content fixtures are deterministic, while asset IDs/payloads and test
certificates are fresh and recorded in the run's receipts; exact byte outputs
and robustness outcomes can vary between runs.

## Remaining qualification work

Representative product datasets, adversarial removal/copying, long load tests,
production certificate operations, synthetic-audio marking, cross-provider
soft-binding interoperability and product-specific legal applicability remain
outside this preview's verified scope. Supported format limits are explicit
and unsupported inputs fail instead of silently yielding unmarked output.

## Dependency check

The installed Python package inventory was checked with pip-audit after
updating cryptography to 50.0.2 and setuptools to 84.2.1. See the
[dependency audit](results/python-dependency-audit.json). This checks known
Python-package advisories, not every native library or operating-system CVE.
Model SHA-256 is verified before deserialization, including first-time setup.
