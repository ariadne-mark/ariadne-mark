# 0.5.1a0 — independent-audit follow-up

This preview addresses the independent audit of commit ba8c199 (0.4.0a0),
received on 4 November 2026. The original audit is preserved unchanged in the
local project `audit-ba8c199/REPORT.md`. Its observations are not silently
relabelled as findings against 0.5.1.

## Existing evidence retained

0.5 already supplied Linux x86-64 offline Docker validation, CPU Fast/Resilient,
real stock-video transformations, resource measurements and minimal video-only
installation. Those are documented in [0.5 validation](0.5.0a0.md); they were not
rerun as a new performance study. Watermark model/profile settings are unchanged.

## Audit disposition

| Finding | Disposition and boundary |
|---|---|
| F1 slow upload holds inference | Fixed reported single-client slot starvation: independent bounded upload slots and total deadline; bounded handlers; slow-client regression. Public edge buffering/rate limiting remains an operator requirement; reference nginx config supplied. |
| F2 untrusted issuer attribution | Headline explicitly says issuer unverified; strict CLI requires trusted credentials; production serve requires configured roots. Raw signed fields remain claims, not independently verified brand identity. Real foreign-signer regression. |
| F3 copied public ID | Misleading source-attribution implication removed. Registry reports exact file hash match or content binding not verified. Real transferred-ID regression. Copy/removal resistance and authenticated linkage after transformation remain open; no perceptual-hash shortcut is represented as authentication. |
| F4 one-frame/spliced video | Per-engine sample coverage, partial/aggregate-only evidence and explicit lack of whole-video coverage. Real splice regression on both new profiles. No arbitrary 4/5 or 90% rejection rule added; the user chose a soft benchmark annotation. Complete watermark recoverability is not inferred from samples. |
| F5 process death during publication | Durable registry insert, fsynced receipt, then media commit marker. Process-death tests at registry, after receipt and after media. Earlier crashes can leave unpublished orphan metadata; generic apps own cleanup/idempotency. Product wrapper reconciles its own unpublished job state. No cross-resource atomic transaction/power-loss SLA claimed. |
| F6 certificate expiry | Preserve built-in TSA trust when adding operator roots; use native trusted signing-time validation. Offline RFC3161 test verifies stamped/unstamped files after a 10-second signer expires. Unstamped unresolved expiry is distinct from tampering. Production signing requires a trusted timestamp. Revocation freshness remains outside offline verification. |
| F7 reader errors | Public C2paError types; runtime/allocation/unknown errors are not_checked; malformed evidence is separate. Real tampering regression retained. |
| F8 mismatched size limits | Default upload and signed export ceiling both 512 MiB. No claim of supporting arbitrary 5-minute CRF18 files regardless of size. Operator lowering upload ceiling must narrow product scope. |
| F9 registry writes from verifier | CLI verify/serve use SQLite mode=ro; product mounts registry directory read-only. Read-only writer-rejection and live-update regression. |
| F10 inflated latent coverage | EU machine mark and CA latent linkage are partial_measure; missing public resolver discovery and authenticated durability are explicit. Normative dates/source snapshot unchanged; official-source reconciliation remains open. |
| F11 infinite worker retries | Single-worker flock retained; bounded attempts, delayed retry and poison-job staging cleanup. Queue regression and HTTP restart acceptance. No distributed lease implementation claimed. |
| F12 demux | Explicit MP4/MOV demux and file protocol for input parsing; no playlist autodetection dependency. |
| F13 created plus parent history | Credentialed input requires action=altered; parent retention remains tested. No silent change of caller's origin claim. |
| F14 traceability/version | Runtime version read from installed distribution; current validation links and technical evidence updated. CPU setup remains explicit; full media extra still needs CPU Torch installation or Docker. |
| F15 ICC/disclosure | ICC input requires explicit color conversion. English visible label remains a reference, with localization/accessibility left explicit. |
| F16 CPU performance | Addressed by separately measured 0.5 Fast/Resilient profiles and asynchronous product queue. Throughput SLA, long-video capacity and cancellation remain open. |
| F17 distribution licenses | Upstream inventory/notices retained and dependency inventory captured. Public binary/container redistribution needs license/source-offer review; no Docker Hub distribution is claimed. |

## Executed validation

Full installed-wheel suite: **81/81**, offline Linux x86-64, 2 CPU / 6 GiB,
non-root, read-only root filesystem. Includes real engines, new attack
regressions, process death and offline TSA expiry. Final logs and exact hashes
are in the project `research/sdk-audit-followup-0.5.1a0/` evidence folder.

The existing stock-product emulator is upgraded using the installed wheel,
without source mounts over the SDK. Acceptance uses six images, three Fast
videos, three Resilient videos, a separate trusted-root verifier, download hash
checks, profile receipts, invalid media, visible disclosure, mid-export worker
loss and service restart. **45/45 HTTP checks passed**, including the interrupted worker and service
restart. The test itself is `examples/stock_product/acceptance.py`.

Private keys, SQLite backups, uploads and test media are excluded from shared
evidence. Public release, legal certification and production readiness are not
asserted by these technical tests.
