# 0.5.0a0 installed SDK validation

Developer preview, 4 November 2026. Fast and Resilient settings are fixed in
`benchmarks/video/profiles/`. Both embed into every frame on CPU. Resilient is
not an assertion of universal durability or a legal compliance tier.

## Real-engine package tests

**67/67 tests passed**, 164.620 seconds. Tests used the installed wheel in the
CPU Docker image, Linux x86-64 / Python 3.12 / Node 20.19.2, 2 CPU / 6 GiB limit,
network disabled, non-root user and read-only filesystem. Coverage includes
images, C2PA, both video profiles, old payload formats, AAC byte/timestamp
preservation, CFR/VFR, portrait/rotation, metadata loss and registry recovery,
concurrent exports and worker failure before publication (including after the
last encoded frame). Full log: `logs/final-tests-r4.log` in the release evidence.

## Full export benchmark

Six stock scenes, each 3 seconds / 720p / 24 fps; 12 complete exports. Warmed
models; m6a.large host (2 vCPU / 8 GiB), container limited to 2 CPU / 6 GiB.
Other product containers were paused. Timings include video processing,
signing, watermark/C2PA read-back and local SQLite registry insertion.

| Profile | Median wall time | Range | Median CPU time | Peak anonymous memory |
|---|---:|---:|---:|---:|
| Fast | 8.93 s | 6.08–10.21 s | 13.93 s | 666 MiB |
| Resilient | 25.65 s | 25.18–26.60 s | 46.04 s | 666 MiB |

This is measured complete processing of 3-second clips, not real-time throughput
or a prediction for every 10-second clip. Memory is sampled cgroup anonymous
memory for export/read-back; blind scans loading additional legacy engines
have a different memory footprint. Cold-start time is excluded from medians
and recorded separately in the event journals.

Each export was tested after CRF28 recompression and after combined trimming
(start 0.37 s, length 1.5 s), resize to 640×360, 15 fps and CRF28 recompression.
Fast recovered the exact ID in **12/12** transformed cases; Resilient **12/12**.
No wrong IDs were accepted. Six unmarked sources per profile produced **0/6**
false positives each. These are six shared negative sources, not twelve
independent ones. Detectors receive no expected ID; stripped files check the
new and legacy engines.

Sources were held out from the profile-selection panel, but earlier Fast
research results existed. This is a controlled integration panel, not a fully
independent unseen-data or general safety evaluation. The earlier selection
panel (Fast 32/36, Resilient 36/36 transformations) remains separate evidence.
90% is a contextual annotation, never a release cutoff or statutory threshold.

## Minimal installation and artifact identity

A separate clean Python environment installs only `wheel[video]`, without
Python Torch, TrustMark or NumPy. Both profiles are smoke-tested offline with
AAC. Node/ONNX models are explicitly provisioned before runtime. Missing legacy
engines are reported as incomplete verification coverage.

Final packaging preserves every tested `ariadne_mark/` source/resource byte;
`tested-source-sha256.json` and `artifact-manifest.json` bind the delivered
wheel to validation. Documentation-only packaging changes are checked
separately from the real-engine test run.
