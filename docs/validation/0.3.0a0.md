# Validation — 0.3.0a0

Tested on 2026-11-03, AWS m6a.large, Linux x86-64, 2 vCPU / 8 GiB host.
Media processes use CPU only, with networking disabled and 6 GiB container limit.
Images remain TrustMark Q/BCH-5; video uses official VideoSeal 1.0 TorchScript,
four-frame streaming batches, BCH-20 + CRC, and up to five verification samples.

## Real stock-video regression

Three Mixkit clips (waterfall, road, clouds), each normalized to 1280×720,
24 FPS, 5 seconds, tested with three different reproducible IDs each.
Source hashes and export IDs are recorded in the [raw report](results/videoseal-stock-0.3.0a0.json).
Media and development signing keys are not included in the public repository.
[Reproduction script](../../benchmarks/video/run.py).

- **9/9 full SDK exports** passed C2PA signature/binding validation and exact ID read-back.
- **10/12 transformed copies** recovered the exact ID: CRF 28, CRF 35, half-size + CRF 28, and 10% center crop + CRF 28 on each first export.
- The clouds clip failed after CRF 35 and after half-size + CRF 28. Both reported `not_found`, not a different ID.
- **0/3 original unmarked clips** returned an ID. This is not a calibrated false-positive rate.

Median complete export was about **34.4 s** per five-second clip; independent signed-file verification was about **1.9 s**. Export includes embedding, H.264 encoding, C2PA signing and read-back. Model initialization is recorded separately; the first export can still include warm-up effects. Peak Python process RSS was about **1.26 GiB**, excluding separate FFmpeg processes. This is a small CPU benchmark, not a throughput SLA.

The earlier raw 256-bit VideoSeal experiment is not a controlled comparison to this release: it used different payloads and no error correction. Do not infer a general robustness ranking from either small sample.

## Regression coverage

**42 tests passed** in the offline CPU container. [Full test log](results/media-tests-0.3.0a0.log). GitHub CI separately builds and tests the standalone image and the installed core wheel on Python 3.11–3.14.

The real-engine suite covers image signatures and recovery, VideoSeal export and recovery, VFR timestamps and decoded presentation end, vertical/rotated video, exact AAC packet preservation, incomplete final batches, legacy TrustMark video dispatch, metadata-stripped recovery, HTTP verification, and atomic refusal to publish failed exports.

BCH tests exercise 420 packet corruptions (0–20 bit flips across 20 IDs), 20 over-capacity cases, and 1,000 random negative packets. These validate the codec implementation, not the watermark detector's real-world false-positive rate. Core tests also cover model checksum failures, conflicting frame/aggregate IDs, missing-engine coverage and metadata-based dispatch.

A known saturated color-bar fixture fails VideoSeal read-back after H.264. It is retained as an explicit rejection regression. Geometry/timing tests use a deterministic unsaturated texture; they do not establish universal content coverage. No strength increase is applied silently to force an export through.

## Remaining work
